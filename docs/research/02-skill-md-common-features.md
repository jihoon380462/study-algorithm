## 2. 결론

1. **이 프로젝트에 그대로 맞는 스킬은 없다.** "Python 알고리즘 교재 + 모바일 우선 + 기기 없이 머릿속 재생"을 목표로 한 스킬은 0개다.
2. 스킬은 세 계열로 나뉜다. 이 프로젝트는 세 계열에서 한 조각씩 필요하다.
   - 대화형 튜터: teach, teach-me, drill-me, tutor, algo-sensei, leetcode-teacher
   - 단일 HTML 시각 설명: talk-to-me-in-html, visual-explainer, explorable, interactive-explainer, tech-visualizer, claude-teacher demo
   - 교재 파이프라인: dmccreary 계열(개념 그래프 → 장 → 시뮬레이션 → 퀴즈), mizchi explainer-book, codebase-to-course
3. **이 프로젝트에 가장 필요한 기능이 기존 스킬에서는 가장 드물다.** 아래 표의 하위권(스텝을 데이터로, 선수 순서 검증, 별도 복습 카드, 난이도 수치 보정, 모바일 수치, 오프라인)이 그대로 직접 써야 할 부분이다.
4. **남의 스킬을 설치하지 말고 패턴만 가져와 프로젝트 전용 스킬을 쓴다.** 이유는 세 가지다.
   - 라이선스: dmccreary 계열은 CC BY-NC(-SA), GarethManning은 CC BY-SA, 5곳은 라이선스 표기가 없다.
   - 무관하거나 위험한 지시: 2개는 명시적으로, 16개는 부분적으로 들어 있다(5절).
   - 데스크톱 전제: 10개가 명시적으로, 7개가 부분적으로 깔고 있다.

## 4. 가져올 패턴과 출처

### 엔진과 내용의 분리
- codebase-to-course: `styles.css`와 `main.js`는 완성본을 그대로 복사만 하고, 에이전트는 장마다 `<section>` 조각과 `data-steps` JSON만 쓴다. 실패 사례를 `gotchas.md`에 모아 완료 전 점검표로 쓴다.
- talk-to-me-in-html: `steps = [{highlight, caption, ...}]` 배열과 `render(i)` 함수 하나.
- claude-teacher demo: 776줄짜리 `template.html`에 엔진이 있고 스킬은 STEPS 5~15개만 채운다.

### 장 골격
- teach-me: 목표 한 문장 → 구체 예 2개 → 원리 → 복습 문항 3~5개. "개념이 둘이면 레슨도 둘." 복습 문항 하나는 반드시 이전 레슨에서 낸다.
- geist-learning-lab: 시간 예산이 붙은 고리. 방향 잡기 30초 → 먼저 답하기 1~3분 → 즉시 피드백 → 설명 1~2분 → 확장 → 점검 30초 → 돌아보기 30초.
- cote-analysis(한국어): 한 줄 핵심 → 시그널 탐지 → 개념 리마인드 → 선택 논증 → 단계별 풀이 → Python 코드 → 함정 → 다른 풀이 → 패턴 카드. 섹션 9개가 문제마다 같은 순서로 온다.
- worked-example-walkthrough: 3~7개 번호 프레임. 프레임마다 상태, 연산, 눈여겨볼 점 한 문장. 가장 작은 비자명 예제를 쓰고 검산으로 끝낸다.

### 숫자 상한
- pdf-to-interactive-web: "간결하게" 대신 글자 수 상한을 적었더니 출력이 11,495자에서 2,710자로 줄었다고 보고한다. 장면 최대 7개.
- talk-to-me-in-html: 청크 5~9개, 청크당 90초 이하, 연속 산문 약 60단어 이하.
- codebase-to-course: 텍스트 블록 2~3문장, 코드 조각 5~10줄, 화면의 절반 이상은 그림.
- visual-explainer: 재생 이벤트 6~12개, "장면마다 주장 하나, 스텝마다 눈에 보이는 변화 하나, 자동 재생 금지."

### 순서와 난이도
- dmccreary book-chapter-generator: "모든 선수 개념이 같은 장이나 앞 장에 있다"를 코드 assert로 위반 0건까지 고친 뒤에만 목차를 보여 준다. 다만 이 스킬은 장당 개념 8~25개짜리 교과서용이다. 이 프로젝트는 장당 새 개념 1개라는 자체 상한을 쓴다.
- mizchi explainer-book: `book.json`에 장마다 `introduces`, `requires`, `minutes`를 선언하고, 검증 스크립트가 도입 전 사용과 읽기 시간 초과를 잡아 실패시킨다. 읽기 시간은 "글자 수 ÷ 500 + 코드 줄 수 ÷ 15"분으로 추정한다(500자는 일본어 기준값이라 한국어로는 직접 재야 한다). 개념 검사는 단순 문자열 일치라 별칭을 등록해야 한다.
- drill-me: 최근 약 7문항의 정답률을 80~90%로 유지한다. 90%를 넘으면 단서를 줄이고, 70% 아래면 예제를 줄이거나 선수 개념으로 돌아간다. 스킬은 이를 "85% 규칙"이라 부르지만, 그 이름의 출처인 논문은 기계 학습 모델에 대한 이론이다. 사람에게 검증된 수치가 아니라 운영 기준으로만 쓴다.
- teach-me: 3연속 정답이면 올리고, 2연속 고전이면 선수 개념으로 돌아간다. 복습 정답률이 60% 아래면 속도가 너무 빠른 것이다.

### 회상
- mattpocock/teach: "레슨은 다시 안 본다. 레퍼런스는 다시 본다." 수업과 요약 카드를 다른 산출물로 나눈다. 기록은 증거가 있을 때만 남긴다.
- retrieval-practice-generator: 문항마다 유형(자유 회상, 단서 회상, 재인)을 표시한다. 배운 지 1주 이내는 단서 회상, 2주가 넘으면 자유 회상 비중을 높인다.
- algo:blank(한국어): 가릴 줄(자료구조 초기화, 핵심 조건, 점화식, 방문 처리, 큐·스택 조작, 반환값)과 남길 줄(import, 시그니처, 변수명, 출력)의 기준표. 가려지는 줄이 곧 외울 줄이다.

### 검증
- pdf-to-interactive-web: HTML에 약속된 `data-*` 표지를 달게 하고, 표준 라이브러리만 쓰는 파이썬 스크립트가 글자 수, 장면 수, 예측 문항 수, 외부 리소스 0개를 센다.
- talk-to-me-in-html: 의존성 없는 린트 스크립트가 `vw` 폭, 텍스트 입력, TODO 자리표시자, 모션 줄이기 누락을 잡는다.
- visual-explainer: 오류가 있으면 렌더 스크립트가 파일을 아예 쓰지 않는다.
- pypeep: 실제 실행 추적만 쓰고 한도 기본값(이벤트 10,000개, 재귀 깊이 200, 10초)을 둔다.

### 모바일 계약
- talk-to-me-in-html: 380px 먼저, 폭은 컨테이너 기준만 쓰고 `vw` 금지, 넓은 표와 코드는 자기 상자 안에서만 가로 스크롤, 터치 타깃 44px 이상, 본문 17px 이상, 텍스트 입력 금지.

### 스킬 포장
- anthropics/skill-creator: description이 발동 조건, 본문은 500줄 미만, 나머지는 번들 파일로 내린다.
- 규격(agentskills.io와 Claude Code 문서, 2026-11-23 확인):
  - 프로젝트 스킬 위치는 `.claude/skills/<이름>/SKILL.md`다.
  - `name`은 1~64자, 소문자·숫자·하이픈만 쓰고 폴더 이름과 같아야 한다. `claude`, `anthropic`은 이름에 쓸 수 없다.
  - `description`은 1~1,024자다. 스킬 목록에서 잘릴 수 있으니 핵심 용도를 맨 앞에 쓴다.
  - 본문 500줄·5,000토큰 미만은 권장이지 강제는 아니다. 참조 파일은 한 단계 깊이로만 둔다.
  - 대화가 길어져 압축되면 스킬 본문은 **앞 5,000토큰만** 다시 붙는다. 어기면 안 되는 규칙은 SKILL.md 맨 위에 둔다.

## 5. 그대로 가져오면 안 되는 것

- **데스크톱 전제.** hover 툴팁, 좌우 2단, 키보드 이동, 최소 폭 768px(tech-visualizer), 1200px 여백 노트(visual-explainer).
- **이름만 단일 HTML.** 대부분 Google Fonts나 Chart.js 같은 CDN을 허용한다. 통신이 없으면 깨진다. 또 이 프로젝트는 trace를 굽는 단계가 어차피 빌드다. "런타임은 무의존, 빌드는 Python 스크립트 하나"로 바꿔 받아들인다.
- **주제마다 테마 바꾸기**(talk-to-me-in-html). 교재는 모든 장이 같은 색 의미를 써야 한다.
- **승인 없이 바로 만들기**(codebase-to-course, interactive-explainer). 목차는 난이도 곡선 그 자체라 승인 단계가 필요하다.
- **마지막 스텝에서 열리는 스테퍼**(visual-explainer). 예측 학습에는 스포일러다.
- **LLM이 손으로 하는 계산**(drill-me의 복습 간격 산술). 함수로 구현한다.
- **가짜 피드백.** leetcode-teacher의 playground 코드는 테스트를 실행하지 않고 난수로 통과 여부를 정한다.
- **무관하거나 위험한 지시.**
  - algo-sensei: 사용자 동의 후 `gh api`로 저장소에 star를 누르게 하는 절이 있다.
  - microsim-generator: 모든 산출물에 "전역 발견용" 메타 태그를 넣도록 강제한다.
  - drill-me: 홈 디렉터리(`~/.drill-me/`)에 상태를 쓴다.
  - visual-explainer, explainer-book: `npx` 실행과 무거운 툴체인을 요구한다.

## 6. 이 프로젝트용 스킬 뼈대(초안)

아직 만들지 않았다. 결정 사항([README](README.md) 4절)이 정해진 뒤 만든다.

```
CLAUDE.md               변하지 않는 사실과 금지 사항
MISSION.md              목표와 종료 조건(한 문단)
curriculum.json         로드맵: 장별 introduces/requires/난이도
glossary.md             용어 단일 원천(금지 별칭 포함)
.claude/skills/new-chapter/
  SKILL.md              300줄 이하
  references/
    chapter-template.md   장 골격
    card-spec.md          재생 카드 3종 규격과 수치
    style-rules.md        코드 폭, 표기, 색 의미
    gotchas.md            실패 사례 누적
  scripts/
    trace.py              실행 추적 → steps JSON
    check_chapter.py      수치 린트
    check_gradient.py     난이도 경사 검사
```

### 왜 CLAUDE.md와 스킬을 나누나
- CLAUDE.md는 매 세션 읽힌다. 짧게 유지하고 "언제나 참"인 것만 둔다: Python 버전, 재고 규칙(통과한 장 + 2까지만 생성), 한 세션 한 장, 실명·직장 정보 금지, 진도 파일 커밋 금지.
- 스킬은 장을 만들 때만 읽힌다. 절차와 규격은 여기에 둔다.
- 클라우드 세션은 저장소 안의 `CLAUDE.md`와 `.claude/`만 읽는다. 개인 PC의 `~/.claude` 설정은 넘어오지 않는다([05](05-tech-and-workflow.md) 참고).

### SKILL.md 절차(한 세션 = 한 장)
1. `curriculum.json`에서 다음 장 하나를 확인한다. 재고 규칙을 넘으면 멈춘다.
2. 실행되는 `.py`를 쓴다. 핵심 함수 15줄 이하, 줄당 36자 권장(상한 40자), 중첩 3단 이하.
3. `trace.py`로 steps JSON을 만든다. 추적표를 손으로 쓰지 않는다. 키프레임은 비교·교환·대입 이벤트 전부다.
4. 재생 카드를 쓴다. 유형은 추적, 정의, 표 가운데 하나다. 숫자로 대조할 수 있는 정답을 넣는다.
5. 고정 골격에 따라 장 본문을 쓴다.
6. `check_chapter.py`와 `check_gradient.py`를 통과시킨다.
7. 360px 화면에서 가로 넘침이 0인지 확인한다.
8. `gotchas.md`를 갱신하고 커밋한다.

종료 조건은 "스크립트 전부 통과 + 미리보기 주소 제시"다. 통과 전에는 완료라고 말하지 않는다.

### 스킬에 반드시 넣을 금지 사항
- 추적표, 프레임, 정답 숫자를 손으로 쓰지 않는다.
- SVG 좌표를 직접 쓰지 않는다. 렌더러가 계산한다.
- 엔진 파일(`player.js`, `styles.css`)을 다시 생성하지 않는다.
- 한 세션에 두 장 이상 만들지 않는다.
- 용어집에 없는 용어, 도입 전 개념을 쓰지 않는다.
- hover, 드래그, 스와이프, 자동 재생, 외부 CDN을 쓰지 않는다.
