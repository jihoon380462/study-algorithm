# 05. 기술 선택과 저작 워크플로

조사일 2026-11-23. 버전과 날짜는 그날 공식 저장소·레지스트리·문서에서 확인한 값이다. 출처와 검증 상태는 [07-sources.md](07-sources.md)에 있다.

## 1. 권장 구조

```
chapters/03-selection-sort/
  algo.py       실행되고 테스트되는 코드(유일한 원천)
  chapter.md    글(고정 골격)
      │
      │  build.py  ← Python 스크립트 하나
      ▼
  trace.json    실제 실행에서 만든 상태 스냅샷 배열
      ▼
site/           정적 HTML + player.js + styles.css
```

- **런타임**: 의존성 없는 커스텀 엘리먼트 하나(`<algo-player>`), 인라인 SVG, CSS 전환.
- **저작**: `.py`와 Markdown.
- **빌드**: Python 스크립트 하나가 trace를 굽고 HTML을 조립한다.
- **검증**: 9절의 검사를 push마다 돌린다.

"빌드 없는 단일 HTML"은 성립하지 않는다. trace를 실제 실행에서 만드는 단계가 곧 빌드다. 대신 런타임 의존성을 0으로 두면 같은 효과(오프라인, 빠른 로딩, 깨질 것이 없음)를 얻는다.

## 3. 추적기

- `sys.settrace`(또는 `bdb`)로 100줄 안팎의 자체 추적기를 쓴다.
- 포맷은 Python Tutor 방식을 참고한다. 스텝마다 완결된 상태 스냅샷을 담고, `line`은 "곧 실행될 줄"이다. Python Tutor는 1,000스텝 한도와 "칠판 한 장 분량"이라는 기준을 둔다.
- Python Tutor 코드를 가져다 쓰지는 않는다. 현재 운영 중인 코드는 공개돼 있지 않고 남은 것은 2019년 포크다.

### 반드시 피할 함정
1. **한 줄 밀림.** `line` 이벤트는 그 줄이 실행되기 *직전*에 온다. 그 시점의 상태는 "앞 줄까지 실행한 결과"다. 마지막 줄의 효과는 `return` 이벤트에서만 잡힌다. `line`과 `return`을 모두 기록하고, 화면의 강조 줄이 "방금 실행한 줄"인지 "다음에 실행할 줄"인지 하나로 정해 스킬에 적는다.
2. **별칭.** 리스트를 그대로 저장하면 모든 스텝이 마지막 상태를 가리킨다. 기록 시점에 값으로 풀어 저장한다. 변수마다 따로 깊은 복사를 하면 "두 이름이 같은 객체를 가리킨다"는 관계가 사라지므로, 객체 id를 기준으로 한 번에 직렬화한다. Python 3.13부터 `frame.f_locals`는 원본에 연결된 프록시라서 그대로 저장하면 안 된다.
3. **너무 긴 추적.** 줄 단위로는 버블 정렬 n=6이 54스텝이다. 키프레임을 "비교·교환·대입 이벤트 전부"로 기계적으로 정의하고, 스텝 수는 n을 줄여 맞춘다. 사람이나 LLM이 스텝을 골라내면 복잡도가 왜곡돼 보인다.
4. **비결정성.** `PYTHONHASHSEED`를 고정한다. set 순회 순서가 실행마다 달라질 수 있다.

추적기 자체를 검사하는 테스트 두 개를 둔다. "`x = 1` 다음 스텝에서 x가 보이는가", "`b = a` 뒤 `b.append(...)`가 a에도 반영돼 보이는가".

### 크기(직접 측정)
| 예제 | 스텝 | 원본 | gzip |
|---|---|---|---|
| 버블 정렬 n=6 | 54 | 7KB | 370B |
| 병합 정렬 n=8 | 148 | 35KB | 970B |
| 예제 150개 추정 | - | - | 약 100KB |

### Python 버전
- 이 클라우드 환경의 `python3`는 3.13.18이다. 최신 안정판은 3.15.2다.
- `heapq`의 최대 힙 함수 5개(`heapify_max` 등)는 3.14부터 있다. 본문은 **부호 반전 관용구**로 통일하고 3.14+ 함수는 참고 상자에만 둔다.
- `.python-version`과 CI에 같은 버전을 적는다.

## 4. 플레이어와 렌더러

- 1판 렌더러는 **하나**다: 배열 + 포인터 이름표 + 보조 구조 한 줄.
- 좌표는 렌더러가 계산한다. 에이전트는 데이터만 선언한다.
- 첫 스텝에서 열린다. 자동 재생은 없다. 하단 고정 버튼 두 개와 k/N 표시만 둔다.
- 색은 의미별 토큰으로 정의하고 모든 장이 같은 뜻으로 쓴다. 테두리나 무늬를 함께 써서 색만으로 구분하지 않는다.
- OS의 다크 모드와 모션 줄이기 설정을 따른다.
- 페이지 구석에 빌드 버전(커밋 해시)을 표시한다. "고쳤는데 안 바뀐다"를 바로 가려낼 수 있다.

## 5. 브라우저 안 Python은 미룬다

- **Pyodide** 314.0.8: 코어 원본 약 13.5MB, 전송 약 6.2~6.4MB. 폰 기본 로딩에 넣을 수 없다.
- **MicroPython** WebAssembly: 원본 450KB(brotli 171KB)로 작다. 그러나 settrace 빌드의 프레임 객체에 `f_locals`가 없어 **지역 변수를 스텝마다 읽을 수 없다.** "같은 추적기를 브라우저에서도 돌린다"는 계획은 MicroPython으로는 안 된다.
- 대안: 빌드 때 입력 프리셋 2~3개(전형, 최악, 경계)를 구워 고르게 한다. 런타임 없이 효과 대부분을 얻는다.

## 6. 복습과 저장

- 1판의 상태는 두 가지뿐이다: 마지막 위치, 카드별 마지막 통과 날짜. `localStorage`에 둔다.
- 복습은 고정 간격표(예: 1, 3, 7, 21일)로 시작한다. 스케줄 함수만 분리해 두면 나중에 바꿀 수 있다.
- ts-fsrs는 미룬다. 6.0.1(2026-11-22)은 API와 기본 알고리즘(FSRS-7)이 바뀐 지 한 달이 안 됐고, 실제 번들은 압축 후 25~40KB이며 Node 24 이상을 요구한다.
- 진도 파일은 저장소에 올리지 않는다. JSON 내보내기·가져오기 버튼과 마지막 백업 날짜를 화면에 둔다.

### iPhone이라면
- Safari는 사이트와 상호작용 없이 "Safari를 쓴 날" 기준 7일이 지나면 그 사이트의 저장소를 지운다.
- 홈 화면에 추가한 웹앱은 이 삭제에서 면제된다. 저장소는 Safari와 분리된다. Safari 탭에서 쌓은 진도는 넘어가지 않는다.
- 첫날 홈 화면에 추가하고 그 아이콘으로만 연다. iOS 26부터는 홈 화면에 추가하면 기본으로 웹앱으로 열린다.

## 7. 호스팅과 공개 범위

### GitHub Pages
- GitHub Free에서는 **공개 저장소에서만** 쓸 수 있다.
- 유료 플랜으로 저장소를 비공개로 해도 **사이트는 공개**다(비공개 게시는 Enterprise Cloud만).
- 한도: 사이트 1GB, 월 100GB, 시간당 10빌드(모두 권장 한도). 개인 교재에는 충분하다.

### Cloudflare
- 비공개 저장소를 연결할 수 있고, 브랜치마다 미리보기 주소가 생기며, Access로 본인만 보게 제한할 수 있다.
- 브랜치 이름의 `/`는 `-`로 바뀐다. `claude/foo` 브랜치의 미리보기는 `claude-foo.<프로젝트>.pages.dev`다.
- Access 정책은 미리보기 주소만 막는다. 본 주소는 따로 설정해야 한다.
- 무료 한도는 월 500빌드다.
- 지금은 새 프로젝트를 Pages가 아니라 Workers(Static Assets)로 시작하라고 안내한다.

### 공개 저장소에서 새는 정보
- 커밋 작성자 이름과 이메일(GitHub noreply 주소로 바꿀 수 있다)
- 커밋 시각(교대 패턴이 드러난다)
- 저장소에 올린 진도·복습 로그
- 본문에 적은 직장·설비 묘사

어느 쪽을 고르든 본문에 실명과 직장 정보를 쓰지 않고, 페이지에 `noindex`를 넣는다.

## 8. 폰에서 Claude Code로 만드는 흐름

- 클라우드 세션은 저장소를 새로 받아 시작한다. **저장소 안의 `CLAUDE.md`와 `.claude/`를 읽는다.** 개인 PC의 `~/.claude` 설정과 사용자 스킬은 넘어오지 않는다. 규칙은 전부 저장소에 커밋한다. (claude.ai 계정에서 켠 스킬은 자동으로 실린다.)
- 저장소의 `.claude/settings.json`에 둔 훅과 권한 규칙은 **저장소 하나짜리 세션**에서만 적용된다. 훅으로 검증을 강제하려면 이 형태로 작업한다. 그렇지 않으면 CI가 유일한 안전망이다.
- 세션 컨테이너는 임시다. 커밋하고 push하지 않은 것은 사라진다.
- **모바일 앱에는 사이트 미리보기가 없다.** 머지 전에 폰으로 볼 방법을 먼저 만든다.
  1. GitHub Pages의 배포 브랜치를 작업 브랜치로 잠깐 바꾼다. 가장 싸지만 빌드 산출물을 커밋해야 하고, 브랜치마다 설정을 손으로 바꿔야 하며, 그동안 평소 쓰는 사이트 주소가 미리보기로 바뀐다.
  2. Cloudflare의 브랜치별 미리보기 주소를 쓴다. 평소 사이트와 미리보기가 분리된다.
  3. `pr-preview-action`으로 PR마다 하위 경로에 올린다.
  4. Claude Code의 Artifact로 한 장짜리 시제품을 비공개 주소에 올려 본다. 단일 페이지여야 하고 외부 리소스 제한이 있다. 내 플랜에서 되는지 확인이 필요하다.
- **한글 글꼴이 다르다.** 클라우드 VM에는 WenQuanYi Zen Hei와 Unifont만 있다. 세션 안 스크린샷은 실제 폰과 한글 폭·줄바꿈이 다르다. 픽셀 비교는 의미가 없고 "360px에서 가로 넘침 0"만 단언한다. 최종 확인은 실제 폰으로 한다.
- 한글 글꼴과 Graphviz는 환경의 설치 스크립트에서 `apt`로 넣을 수 있다. 스크립트는 약 5분 안에 끝나야 결과가 캐시된다(직접 설치해 보지는 않았다).
- 한 세션은 한 장만 다룬다. 여러 장을 한 번에 만들면 뒤로 갈수록 얇아진다.

## 9. 검증 게이트

push마다 자동으로 돌린다. 하나라도 실패하면 그 장은 완료가 아니다.

1. 모든 `algo.py` 실행과 단언(assert) 통과

6. 난이도 경사 검사([04](04-curriculum.md)의 규칙)
7. 용어 린트: 용어집의 금지 별칭이 본문에 없음
8. 360px 화면에서 가로 넘침 0

## 11. 미리 만들지 않을 것

1장을 폰에서 확인하기 전에는 아래를 만들지 않는다.

- 서비스 워커와 설치 유도(통신이 안 되는 작업장일 때만 최소 캐시)
- 트리·그래프·호출 트리 렌더러
- 적응형 복습 알고리즘
- 검색, 진도 대시보드, 달력, 동기화
- 픽셀 단위 스크린샷 회귀 테스트
- 여러 장을 병렬로 만드는 서브에이전트 구성

시작 분량의 기준은 추적기 약 100줄, 플레이어 약 200줄, 배열 렌더러 하나다.
