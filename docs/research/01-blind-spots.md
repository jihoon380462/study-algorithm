# 01. 놓치고 있는 것

요청에 담긴 계획은 다섯 가지였다. Python 코드 기반, 시각적, 모바일 우선, 공장에서 머릿속으로 흐름과 공식 떠올리기, 장 사이 난이도가 완만할 것.

아래는 그 계획에 빠져 있는 것이다. 조사에서 근거를 찾은 것만 실었다. 출처는 [07-sources.md](07-sources.md)에 있다.

- ★★★ 설계 자체를 바꾼다
- ★★ 1판에 반영한다
- ★ 알아 두면 된다

## 1부. 학습 방식

### 1. 진짜 학습은 화면 밖에서 일어난다 ★★★
- 사이트를 "보면서 배우는 것"으로 설계하면 어긋난다. 실제 사용은 **휴식 때 싣고 → 작업 중 머릿속으로 돌리고 → 다음 휴식 때 확인**하는 순서다.
- 조사한 시각화 사이트 24곳, 교재 22곳, 스킬 36개 가운데 기기 없이 떠올리도록 설계된 것은 없었다.
- 그래서 장마다 **재생 카드**가 필요하다. 불변식 한 문장, 10줄 안팎의 코드, 고정된 작은 입력, 전체 추적표, 숫자로 대조하는 정답, 머릿속 과제 3개로 이뤄진다. 사이트의 나머지는 이 카드를 싣고 확인하는 수단이다.

### 2. 보기만 해서는 늘지 않는다 ★★★
- 알고리즘 시각화 연구를 모은 메타 연구(Hundhausen 외, 2002)의 결론은 "무엇을 보여 주느냐보다 학습자가 무엇을 하느냐가 효과를 정한다"이다.
- 다시 읽기만 한 집단은 일주일 뒤 40%를 기억했고, 떠올리기를 반복한 집단은 61%를 기억했다. 그런데 자신감은 다시 읽은 쪽이 더 높았다(Roediger & Karpicke, 2006, 산문 지문 실험). 직후 점수는 다시 읽은 쪽이 오히려 높아서(83% 대 71%), 떠올리기는 할 때마다 "덜 되는 느낌"이 든다. 그 느낌이 정상이다.
- 반영: 스테퍼는 "다음 스텝 예측 → 탭 → 확인"으로 만든다. 자동 재생은 넣지 않는다. 복습 카드는 떠올린 뒤에만 정답을 연다.

### 3. 속으로만 떠올리면 효과가 약할 수 있다 ★★★
- 이 프로젝트의 핵심 가정은 "공장에서 머릿속으로 돌리면 공부가 된다"이다. 근거는 갈린다. 단순한 단어 목록에서는 속으로 떠올리기와 소리 내어 답하기의 효과가 같았다(Smith 외, 2013). 그러나 여러 요소로 된 "정의" 수준의 자료에서는 속으로 떠올리기가 다시 읽기와 차이가 없었다(Tauber 외, 2018). 복잡한 자료는 속으로 떠올릴 때 끝까지 가지 않고 멈추기 때문이라는 설명이 있다.
- 알고리즘 추적 같은 절차 자료로 이를 비교한 연구는 찾지 못했다.
- 반영:
  - 머릿속 과제의 답을 **한 덩어리**로 만든다. 최종 배열, 숫자 하나, 다음 한 스텝.
  - 폰을 볼 때 답을 **탭으로 고른 뒤** 정답을 연다. 속으로만 끝내지 않는다.
  - 불변식 문장은 속으로 끝까지 말한 뒤 대조한다.
  - "머릿속 재생만으로 충분하다"고 기대하지 않는다. 주 1회 종이나 키보드로 확인한다.

### 4. 머릿속 재생에는 크기 한계가 있다 ★★★
- 작업 기억은 대략 3~5덩어리다(Cowan, 2001).
- Python 코드 읽기 문제에서 추적 과정을 끝까지 적은 응답은 82%가 맞았고, 아무것도 적지 않은 응답은 61%가 맞았다(Cunningham 외, 2017). 실험이 아니라 상관 관계다. 같은 연구에서 **하다 만 추적은 안 적은 것만큼 나빴다.** 머릿속 추적은 끝까지 갈 수 있는 크기여야 한다.
- 반영: 머릿속 카드는 **원소 5개 이하, 살아 있는 변수 3개 이하, 12스텝 이하**로 묶는다. 넘으면 예제를 줄이거나 "종이 필요" 등급을 붙인다. 이 규격은 빌드 린트로 강제한다.

### 5. 재귀와 DP는 추적으로 외울 수 없다 ★★
- 재귀 호출을 머릿속으로 따라가면 호출 스택이 작업 기억을 넘는다.
- 반영: 카드를 세 종류로 나눈다.
  - **추적 카드**(반복문 알고리즘): 고정 입력과 추적표
  - **정의 카드**(재귀): 함수가 하는 일 한 문장 + 기저 조건 + 귀납 한 줄
  - **표 카드**(DP): 칸의 뜻 → 점화식 → 초기값 → 채우는 순서

### 6. 복습이 없으면 뒤 장이 어려워진다 ★★★
- 앞 장의 불변식을 잊으면 뒤 장에서 새로 익힐 것이 두 개가 된다. 난이도 급등의 숨은 원인이다.
- 반영: 고정 간격 복습을 넣고, 홈 첫 화면을 "오늘 머릿속으로 돌릴 3개"로 한다. 복습이 밀려 있으면 새 장을 권하지 않는다.

### 7. 추적할 줄 아는 것과 쓸 줄 아는 것은 다르다 ★★
- 프로그래밍 교육 연구는 추적 → 설명 → 작성의 단계를 구분한다. 추적만으로는 빈 화면에서 코드를 쓰지 못한다.
- 반영: 목표를 먼저 정한다(이해와 지루함 해소인지, 코딩 테스트까지인지). 장마다 "이 줄을 바꾸면?" 변형 질문을 하나 넣고, 주 1회 집에서 10분 타이핑이나 빈칸 채우기를 한다.

### 8. "공식"은 복잡도만이 아니다 ★★
외울 대상은 네 종류다.
- 불변식: "i 왼쪽은 정렬돼 있다"
- 점화식: `dp[i] = dp[i-1] + dp[i-2]`
- 인덱스 공식: 힙의 자식 `2*i+1`, `2*i+2`, 원형 큐 `(i+1) % n`, `mid = (lo+hi)//2`
- 복잡도 한 줄

카드의 공식 칸은 장마다 한 줄로 두고, 전체를 모은 공식 색인 페이지를 만든다.

## 2부. 안전과 작업장

### 9. 머릿속 추적은 주의를 많이 쓴다 ★★★
- 운전 중 인지 분산 연구(AAA 재단, 2013)는 "계산하면서 단어를 기억하는" 과제를 척도의 최고점으로 삼았다. 이런 과제는 반응을 늦추고 주변을 살피는 횟수를 줄인다. 머릿속 상태 추적이 이와 비슷하다는 것은 **유추**다. 직접 잰 연구는 없다.
- 기계 작업 중에 일부러 하는 암산을 다룬 연구는 찾지 못했다. 가까운 연구들은 결과가 엇갈린다. 계기 감시 중 덧셈은 놓침을 늘리지 않았지만 잘못된 반응을 늘렸다는 1964년 실험이 있다.
- 근거가 이 정도이므로 안전은 연구 수치가 아니라 **행동 규칙**으로 지킨다.
  - 설비를 조작하거나, 이동하거나, 판단이 필요한 감시를 할 때는 하지 않는다. 멈춰서 대기하는 동안에만 한다.
  - 과제를 두 등급으로 나눈다. **가벼움**(불변식·공식 암송)과 **무거움**(상태 추적).
  - 과제는 30~60초 안에 끊을 수 있게 만든다.
  - 0장에 이 규칙을 싣는다. 사업장 규정이 사이트 설계보다 먼저다.

### 10. 폰을 실제로 얼마나 볼 수 있는지가 설계를 정한다 ★★★
- 한국에는 작업 중 휴대폰을 일반적으로 금지하는 법령을 찾지 못했다. 사업장 규정에 따른다. 보행 중 사용을 금지한 대기업 사례가 있고, 물류센터처럼 반입 자체를 제한하는 곳도 있다.
- 귀마개를 쓰는 소음 구역에서는 이어폰이 사실상 불가능하다.
- 반영: 확인 전까지 **"폰은 휴식 시간에만"**을 기본으로 설계한다. 카드 싣기 1분, 확인 1분. 반입이 안 되는 곳이면 인쇄용 포켓 카드를 쓴다(A4 한 장에 105×74mm 카드 8개).

### 11. 손과 조명 ★
- 장갑을 끼거나 손이 더러우면 드래그, 스와이프, 작은 버튼이 실패한다. 하단의 큰 버튼 두 개만 둔다.
- 밝은 조명에서는 밝은 배경이 읽기 쉽다. 다크 모드의 배터리 절감은 실내 밝기에서 3~9%뿐이다.

## 3부. 난이도

### 12. "완만하게"는 감으로 지킬 수 없다 ★★★
- 에이전트에게 "난이도를 천천히 올려라"고 쓰는 것으로는 지켜지지 않는다. 숫자와 검사 스크립트가 필요하다.
- 반영: 장마다 메타데이터(새 개념 1개, 선수 장, 추적 상태 크기, 코드 줄 수, 제어 구조 수준)를 적고 빌드에서 검사한다. 규칙은 [04](04-curriculum.md)에 있다.

### 13. 급경사 지점은 이미 알려져 있다 ★★★
여러 커리큘럼과 교육 연구가 같은 곳을 가리킨다.
- 반복문 → 재귀
- 재귀 → 백트래킹
- 메모이제이션 → DP 표
- 1차원 DP → 2차원 DP
- BFS → 가중치 최단 경로
- 해시 테이블 내부, 분할 상환 분석, 그리디 증명

이 지점마다 다리 장을 놓는다. 예: 재귀 앞에 호출 스택, DP 앞에 메모이제이션한 피보나치, 다익스트라 앞에 간선 완화.

### 14. 난이도는 여러 축에서 동시에 뛴다 ★★
- 새 개념, 새 Python 문법, 예제 크기, 코드 줄 수, 증명 부담이 한 장에서 함께 오르면 급경사다.
- 반영: 한 장에 새 Python 기능은 1개 이하. 제어 구조 수준과 증명 부담은 같은 장에서 함께 올리지 않는다.

### 15. 내 기록으로 급경사를 찾는 장치가 없다 ★★
- 반영: 카드마다 "막혔다" 표시를 둔다. 두 장 연속 막히거나 한 장에 사흘 넘게 머물면, 다음 장으로 가지 않고 그 사이에 다리 장을 끼운다. 이 절차를 스킬에 적는다.

### 16. 정식 입력을 정해 두지 않았다 ★★
- 같은 5원소 배열과 같은 그래프를 여러 장에서 다시 쓰면, 새 장에서 새로 익힐 것이 알고리즘 하나로 줄어든다. 정렬 알고리즘끼리 비교도 머릿속에서 된다.

### 17. 용어와 표기가 장마다 흔들린다 ★★
- 한국어 용어는 통일돼 있지 않다(이진·이분 탐색, 덱·데크, 재귀·되부름). TTA 용어사전은 알고리즘 용어가 적고 통용어와 어긋난다.
- 반영: `glossary.md` 하나를 원천으로 두고 금지 별칭을 린트로 잡는다. 0부터 세는 인덱스, 반열린 구간 `[lo, hi)`, 변수 이름(`lo`, `hi`, `mid`, `i`, `j`), 색의 의미를 처음에 고정한다.

## 4부. 정확성

### 18. AI가 손으로 쓴 추적표는 틀린다 ★★★
- 한 줄 밀린 설명이나 틀린 추적표를 그대로 반복해 외우게 된다. 혼자 쓰는 교재라 잡아 줄 사람이 없다.
- 반영: 추적표, 프레임, 정답 숫자는 실제 실행 결과만 쓴다. 설명문의 수치 주장마다 코드 단언을 붙인다([05](05-tech-and-workflow.md) 3절, 9절).

### 19. Python만의 함정 ★★
교재가 한 번씩 짚어야 할 것들이다.
- `list.pop(0)`과 `insert(0, x)`는 O(n)이다. 큐는 `deque`로 쓴다.
- `[[0]*m]*n`은 같은 행을 n번 가리킨다.
- 재귀 한도가 약 1,000이다. 반복형 DFS도 함께 싣는다.
- `heapq`는 최소 힙이고 값 줄이기 연산이 없다.
- `set` 순회 순서는 믿을 수 없다.
- 슬라이싱은 복사라 비용이 든다.
- 가변 기본 인자, 조용히 동작하는 음수 인덱스.
- 표준 라이브러리에 균형 이진 탐색 트리가 없다(`bisect`로 대신).

### 20. Python 버전을 정하지 않았다 ★
- 버전에 따라 쓸 수 있는 함수가 다르다. 빌드 환경과 교재 내용의 버전을 맞춰 고정한다([05](05-tech-and-workflow.md) 3절).

## 5부. 만드는 과정

### 21. 도구 만들기가 공부를 대신한다 ★★★
가장 가능성이 높은 실패다.
- 개인 위키를 십 년 동안 예닐곱 번 다시 만들고 "고급 형태의 미루기"였다고 돌아본 사례가 있다.
- 공개 온라인 강좌 221개의 수료율은 중앙값이 12.6%였고, 과정이 길수록 낮았으며, 첫 1~2주가 결정적이었다(Jordan, 2015). 혼자 쓰는 교재에 그대로 옮길 수 있는 숫자는 아니지만 방향은 참고할 만하다. 1~3장의 완성도와 폰 사용성을 가장 먼저 확인한다.
- 반영:
  - 코드를 쓰기 전에 **종이 카드 3장으로 3근무일** 써 본다([06](06-pilot-cards.md)).
  - 3장을 완성한 뒤 엔진을 동결한다. 새 기능은 재생 기록이 쌓인 뒤에만 넣는다.
  - 주간 기록에 "머릿속 재생 횟수"와 "엔진 커밋 수"를 나란히 적는다.

### 22. AI는 내가 배우는 속도보다 빨리 만든다 ★★★
- 에이전트는 하루에 10장을 만들 수 있고 학습은 주 2~3장이다. 읽지 않은 장이 쌓이면 부담과 불신이 된다.
- 반영: **통과한 장 + 2까지만** 만든다. 한 세션에 한 장만 만든다.

### 23. 전체 목록은 계획이 아니라 지도다 ★★
- 전체 순서(약 150개 단위)는 선수 관계 지도로만 저장소에 둔다. 1판의 약속은 첫 14장이다. 14장 시점에 통과율과 "막혔다" 기록을 보고 계속할지 형식을 바꿀지 정한다.

### 24. 폰으로 만드는 흐름을 먼저 깔아야 한다 ★★
- 모바일 앱에는 사이트 미리보기가 없다. 머지 전에 폰으로 볼 주소가 없으면 깨진 장이 그대로 들어간다.
- 클라우드 세션은 저장소 안의 설정만 읽는다.
- 세션 안 스크린샷은 한글 글꼴이 실제 폰과 다르다([05](05-tech-and-workflow.md) 8절).

### 25. 남의 스킬을 그대로 설치하면 안 된다 ★★
- 라이선스가 비영리·동일조건이거나 아예 없는 것이 많고, 무관한 지시(저장소 star 유도 등)가 섞여 있다([02](02-skill-md-common-features.md) 5절).

### 26. 조사에서 "필수"로 나왔지만 1판에서 뺄 것 ★★
혼자 쓰는 1판 기준이다.
- 전체 목록 한꺼번에 생성 → 첫 14장만
- 사이트 프레임워크 → Python 빌드 스크립트 하나
- PWA 설치 유도와 업데이트 UI → 통신이 안 될 때만 최소 캐시
- 적응형 복습(FSRS) → 고정 간격
- 브라우저 안 Python 실행 → 빌드 때 구운 프리셋
- 빈칸 채우기, 순서 맞추기, 숙달 잠금 → 1판 이후 판단
- 자동 재생, 스크러버, 스와이프 → 큰 버튼 두 개
- 트리·그래프 렌더러 → 배열 렌더러 하나
- 300개 개념 그래프 → 장 메타데이터와 20줄짜리 검사
- 검색, 마인드맵, 툴팁 → 목차와 용어집 한 페이지씩
- 다크 모드 토글, 글자 크기 설정 → OS 설정 따르기
- 진도 대시보드, 연속 기록, 알림, 동기화 → 내보내기 버튼 하나
- 오디오 → 이어폰 허용이 확인된 뒤
- 외부 채점 사이트 연동 → 1판 이후 목표를 다시 정할 때

## 6부. 운영

### 27. 진도가 사라질 수 있다 ★★
- iPhone의 Safari는 일정 기간 쓰지 않은 사이트의 저장소를 지운다. 홈 화면에 추가한 웹앱은 예외다.
- 반영: 상태를 작게 유지하고, 내보내기·가져오기 버튼과 마지막 백업 날짜를 둔다([05](05-tech-and-workflow.md) 6절).

### 28. 작업장에서 통신이 되는지 모른다 ★
- 통신이 되면 1판은 가벼운 정적 페이지로 충분하다. 안 되면 최소한의 캐시가 1판에 들어가야 한다.

### 29. 교대 근무와 화면 잠금 ★
- "하루"의 경계를 자정으로 잡으면 야간조에서 복습 날짜가 꼬인다. 날짜 대신 "마지막 통과 뒤 지난 시간"으로 계산한다.
- 폰을 주머니에서 꺼냈을 때 3초 안에 보던 카드의 정답에 닿아야 한다. 카드마다 고정 주소를 주고 마지막 위치를 저장한다.

### 30. 공개 범위를 저장소를 만들 때 정해야 한다 ★★
- 무료 GitHub Pages는 공개 저장소에서만 되고, 사이트는 어느 경우든 공개다. 커밋 시각은 근무 패턴을 드러낸다([05](05-tech-and-workflow.md) 7절).

### 31. 기존 자료의 라이선스 ★★
- Hello Algo는 글·코드·그림 전체가 비영리·동일조건이다. 구조만 참고한다([05](05-tech-and-workflow.md) 10절).

### 32. 외부 서비스는 사라질 수 있다 ★
- 백준 온라인 저지는 2026-04-28에 종료했다가 운영사가 바뀌어 2026-11-20에 다시 열렸다. 교재의 핵심 경로는 자체 예제로 완결하고, 외부 문제 링크는 선택 항목으로만 둔다.

### 33. 오디오는 매력적이지만 1판에서 뺀다 ★
- 이어폰 허용 여부가 확인되지 않았다. 웹 음성 합성은 카카오톡 같은 Android 인앱 브라우저에서 지원되지 않고, 화면이 잠긴 동안 계속 재생된다는 근거도 찾지 못했다. 꼭 필요하면 빌드 때 만든 mp3 파일이 검증 가능한 길이다.
